<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pydantic model → SQLite store | Model JSON is serialized into a SQLite TEXT column via the store's SQL. |
| untrusted JSON blob → model_validate_json() | A stored/fixture blob is deserialized back into the typed model. |
| SQLite file path → filesystem | The store opens a DB file by path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-T | Tampering | store.py write_run/read_run SQL | mitigate | Parameterized queries only (? placeholders), no dynamic table names, no f-string SQL — asserted by grep in acceptance criteria (Security Domain). |
| T-01-D2 | Tampering | model_validate_json() on an untrusted/old blob | mitigate | Pydantic validates against the schema (no arbitrary object construction); extra="ignore" drops unknown keys; old-schema fields default to None — covered by test_old_schema_loads. |
| T-01-P | Tampering | SQLite file path handling | mitigate | DB opened by explicit caller-supplied path; no path interpolation into SQL; .db documented as local+gitignored for later real data. |
| T-01-I | Information Disclosure | record_json blob contents | accept | Phase 1 stores no secrets (auth is Phase 4); blob may later hold page URLs only. Re-evaluate at Phase 4. |
</threat_model>
