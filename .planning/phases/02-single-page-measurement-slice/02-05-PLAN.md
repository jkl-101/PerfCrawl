## Phase Goal

**As a** PerfCrawl developer auditing any URL, **I want to** run `perfcrawl measure <url>` against a real site and have it actually return Lighthouse scores + Core Web Vitals + network facts on disk, **so that** the proven Python-orchestrator / Node-Lighthouse-over-CDP seam ships end-to-end instead of working only under mocked subprocesses.

(This plan does not introduce new user-visible surface. It closes three Critical findings from `02-REVIEW.md` that block the SC#5 real-network smoke documented in `02-VERIFICATION.md`. The vertical slice the gap closure restores is the exact slice 02-04 promised — `perfcrawl measure <url>` end-to-end — but which currently dies at the worker→Python pipe handoff before any byte of real Lighthouse output reaches disk.)

<objective>
Close the three Critical findings (CR-01, CR-02, CR-03) carried over from `02-REVIEW.md` and re-flagged by `02-VERIFICATION.md` as the reason SC#5 (real-network end-to-end smoke) fails. After this plan, `uv run pytest -m e2e tests/test_e2e.py -x` goes green against `https://example.com/` and the SC#1/SC#5 vertical slice from the ROADMAP — which 02-04 promised but never proved in real execution — is actually achieved.

Purpose:
- CR-01: the Node worker's `process.stdout.write(payload)` followed by synchronous `process.exit(0)` truncates real LH payloads (200KB-2MB) at the ~64KB kernel pipe buffer, so `json.loads(proc.stdout)` in `lighthouse_worker.py:91` raises `JSONDecodeError`, `run_one_sample` returns `None`, the orchestrator's D-14 retry sees the same truncation, the sample drops, all samples drop, `measure_url` raises `MeasurementError('all N samples failed')`. Reproduced by the verifier on 2026-05-29 against `https://example.com/` (exit 2; stderr `measurement failed: all 1 samples failed`). The fix is the callback form of `process.stdout.write(payload, (err) => process.exit(...))` so the kernel drains the pipe before the worker exits.
- CR-02: `chrome.kill()` (orchestrator.py:250) and `proc.kill()` (orchestrator.py:120) are never followed by `.wait()` to reap exit status, so killed Chromium stays a `<defunct>` zombie until the Python interpreter exits. The fix is `chrome.wait(timeout=5)` with `subprocess.TimeoutExpired` catch after every kill.
- CR-03: `_launch_chrome_with_cdp_port` (orchestrator.py:120-123) raises `MeasurementError` on the DevToolsActivePort timeout WITHOUT `shutil.rmtree(user_data_dir, ignore_errors=True)`. Because the assignment `chrome, port, user_data_dir = _launch_chrome_with_cdp_port()` never completes, the caller's finally never runs, the tempdir leaks every time. The fix is to make the launcher self-contained on its failure path.

    ```javascript
      const [reportJson, reportHtml] = result.report;
    ```

    ```python
    def test_worker_drains_large_stdout_payload(tmp_path: Path):
        """CR-01 regression: a >1MB stdout payload survives the Node->Python pipe.

        Verifier finding (02-VERIFICATION.md gap #1):

          "Add a regression test that pumps a >1 MB synthetic payload through the
           worker subprocess (real subprocess, not mocked) and asserts Python
           parses the full JSON."

        This test does NOT invoke the real lighthouse-worker/run.mjs — that would
        require Node + chrome-launcher + a target URL (the e2e-suite's territory).
        Instead it writes a tiny shim script using the SAME drain-before-exit
        pattern Task 1 introduces (process.stdout.write(payload, (err) => ...))
        and spawns it via subprocess.run. If this test goes red, the worker's
        stdout handoff pattern is broken at the language/runtime level, not just
        at the Lighthouse-specific level.

        The shim emits a 1.5MB JSON envelope (well above the ~64KB Linux pipe
        buffer and the ~16KB macOS pipe buffer) and asserts Python receives
        every byte intact.

        Skipped (not failed) when `node` is not on PATH so CI without Node
        passes cleanly.
        """
        node = shutil.which("node")
        if node is None:
            pytest.skip("node binary not on PATH; CR-01 regression requires Node runtime")

        big_chunk = "x" * 1_500_000  # 1.5 MB — comfortably above all pipe buffers
        shim = tmp_path / "shim.mjs"
        shim.write_text(
            "const payload = JSON.stringify({"
            "lhr:{lighthouseVersion:'13.3.0'},"
            f"reportJson:'{big_chunk}',"
            f"reportHtml:'{big_chunk}'"
            "});\n"
            # Mirror Task 1's drain-before-exit pattern verbatim.
            "process.stdout.write(payload, (err) => {\n"
            "  if (err) { process.stderr.write(String(err)); process.exit(1); }\n"
            "  process.exit(0);\n"
            "});\n"
        )

        proc = subprocess.run(
            [node, str(shim)],
            capture_output=True,
            text=True,
            encoding="utf-8",
            timeout=10,
        )
        assert proc.returncode == 0, f"shim exit {proc.returncode}; stderr={proc.stderr}"
        # Sanity: stdout is bigger than any pipe buffer we'd ever encounter.
        assert len(proc.stdout) > 1_000_000, (
            f"stdout truncated at {len(proc.stdout)} bytes — drain failed"
        )
        # The whole envelope round-trips through json.loads (the same call
        # lighthouse_worker.py:91 makes against the real worker).
        parsed = json.loads(proc.stdout)
        assert parsed["lhr"]["lighthouseVersion"] == "13.3.0"
        assert len(parsed["reportJson"]) == 1_500_000
        assert len(parsed["reportHtml"]) == 1_500_000
        assert all(c == "x" for c in parsed["reportJson"][:1000])
    ```
